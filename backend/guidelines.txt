 03  GRADING RUBRIC  (Total: 30 Marks)  
Each phase is assessed holistically across three performance levels: Excellent  (full marks), Satisfactory  
(partial marks), and Insufficient  (zero).  Partial marks within each band are awarded at the marker's 
discretion.  
Phase 1 — Requirement Discovery & Traceability  
Criterion  Excellent (Full Marks)  Satisfactory (Partial)  Insufficient (Zero)  
Actor Classification  All three actor types 
(Primary, Supporting, 
Offstage) correctly 
identified with clear 
rationale  Two actor types defined; 
minor omissions or 
unclear rationale  One or no actor types 
addressed  
Traceability Heatmap  Complete matrix with zero 
orphaned requirements  
every feature are 
implemented and  justified  Matrix present but 1 –2 
orphaned requirements or 
missing justifications  No matrix, or matrix is 
largely incomplete  
Persona Discovery  At least 5 hidden 
requirements or edge 
cases uncovered via AI 
user avatar with clear 
reasoning  3–4 edge cases 
uncovered; some lack 
depth or justification  Fewer than 3 edge cases 
or persona exercise not 
conducted  
Phase 2 — Design & Specification  
Criterion  Excellent (Full Marks)  Satisfactory (Partial)  Insufficient (Zero)  
Gherkin Scripts  All core user stories 
translated to well -formed 
Given/When/Then with 
scenario outlines where 
appropriate  Most stories covered; 
minor syntax issues or 
missing edge scenarios  Fewer than half of stories 
covered, or Gherkin 
syntax incorrect 
throughout  
QA Refinement Loop  All vague adjectives 
replaced with measurable 
metrics; senior QA audit 
log provided  to eliminate 
unquantifiable adjectives 
like "fast" or "secure" and 
replace them with 
measurable technical 
metrics.  Most adjectives quantified; 
1–2 remain vague  Vague terms remain 
unquantified; no audit log  
UML Diagrams  Correct SSD  (System 
Sequence Diagrams ) 
(happy + failure paths) 
and Activity diagram with 
code decision points; 
notation accurate  Diagrams present but 
missing failure path or 
decision points; minor 
notation errors  Diagrams missing or 
fundamentally incorrect  
API Contracts & 
Information Hiding  Clear interface definitions; 
internal stack fully hidden; 
contracts enable 
independent development  Interfaces defined but 
some internal details leak 
or contracts are 
incomplete  No API contracts or no 
separation of interface 
from implementation  
 
 
 Phase 3 — Test-Driven Implementation  
Criterion  Excellent (Full Marks)  Satisfactory (Partial)  Insufficient (Zero)  
Failing Test First  Failing unit tests written 
before implementation; 
tests establish a clear 
mathematical boundary  Tests written but some 
produced after code, or 
boundaries poorly defined  No failing -first evidence, 
or tests absent  
Edge Case Cage 
(Padlocks)  Boundary, threshold, and 
extreme constraints all 
addressed; AI 
hallucination blocked for 
all cases  At least two padlock types 
applied; some edge cases 
unaddressed  Padlocks absent or only 
one constraint type 
applied  
TDP Iteration  Iterative prompting 
documented; final code 
demonstrably fits the test 
boundary; prompt 
appendix complete  Some iteration shown; 
minor misalignment 
between test and final 
logic No iteration documented; 
code does not match test 
boundary  
Vertical Slicing  UI / Logic / DB delivered

monolithic or incomplete 
implementation

Criterion  Excellent (Full Marks)  Satisfactory (Partial)  Insufficient (Zero)

Verification vs
